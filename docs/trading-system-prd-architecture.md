# A股自动复盘与交易计划系统 PRD / 架构方案

更新日期：2026-06-23

## 1. 产品定位

面向小范围团队的 A 股短线/波段自动复盘与交易计划平台。系统不接券商 API，不做自动下单；核心价值是把公开行情、板块资金、新闻催化、个股技术结构、交易纪律和仓位规则自动整合，生成可执行的每日复盘、早间新闻、午间复盘、盘后完整版复盘、个股打分和买卖计划，并发布到公网。

长期方向是订阅制投研产品，因此第一版需要从一开始保留内容归档、自动发布、免责声明、数据源标记和任务状态能力。

## 2. 当前已有基础

当前仓库已经具备以下可复用能力：

- 静态看板：`dashboard/index.html`、`dashboard/app.js`、`dashboard/styles.css`。
- 公网发布雏形：`.github/workflows/publish-dashboard.yml` 会定时生成数据并发布 GitHub Pages。
- 行情复盘数据：`dashboard/scripts/fetch_daily.py` 采集指数、涨跌停、炸板、行业/概念资金、强弱板块、风险雷达和明日观察计划。
- 数据快照：`dashboard/data/daily.json` 和 `dashboard/data/refresh-status.json`。
- 静态站点构建：`dashboard/scripts/build_static_site.py`。
- 个股计算器：`skills/short-term-stock-calculator/scripts/calculator.py` 支持股票代码输入，输出 100 分短线评分、MA20、ATR、量价、买点、止损和仓位建议。
- 交易规则文档：`短线游资交易系统.md` 已定义市场温度、情绪周期、题材排序、股票池、评分、买点、仓位和止损止盈。
- 飞书归档脚本：`dashboard/scripts/write_feishu_bitable_report.py` 可作为内部归档或通知的备选。

第一阶段应在这些能力上增量扩展，而不是重写系统。

## 3. 第一阶段目标

第一阶段成功标准：

- 每个交易日自动生成并发布早间、午间、盘后复盘。
- 首页第一屏展示今日市场状态，移动端浏览器可读。
- 支持输入股票代码或名称，输出个股评分、买卖计划、仓位建议和风险提示。
- 每日保存快照，用于历史归档和后续复盘。
- 定时任务失败时在看板中显示任务状态、失败原因和最近成功时间。
- 所有公开内容默认带有免责声明：仅为个人复盘与交易计划记录，不构成投资建议。

暂不做：

- 券商 API 下单。
- 自动交易。
- 复杂回测。
- 订阅付费、权限系统和用户管理。
- 人工编辑器。第一版以自动生成和自动发布为主。

## 4. 核心用户流程

### 4.1 团队成员每日查看

1. 打开公网首页。
2. 第一屏查看今日市场状态：指数、情绪分、市场温度、任务状态。
3. 查看早间新闻、午间复盘或盘后完整版。
4. 查看明日计划、关注板块、候选股票池和风险提示。
5. 如需查个股，在计算器输入代码或名称，得到评分和计划。

### 4.2 系统每日自动运行

1. 早间任务采集隔夜新闻、政策、公告、外围市场和 A 股映射。
2. 11:30 任务生成午间复盘，结合上午指数、板块资金、涨跌停、炸板、强弱方向。
3. 15:30 任务生成收盘快照，更新市场数据。
4. 21:00 任务生成完整版复盘，结合公告、龙虎榜、晚间新闻和明日计划。
5. 每次任务写入快照、报告、任务状态，并发布公网。

## 5. 功能需求

### 5.1 今日市场状态首页

第一屏必须包含：

- 交易日、当前报告阶段、生成时间、最近任务状态。
- 上证指数、深成指、创业板指、科创50。
- 市场情绪分：涨停、跌停、炸板率、连板高度、概念资金正向数量。
- 市场温度：强 / 中 / 弱 / 冰。
- 情绪周期：冰点 / 修复 / 发酵 / 高潮 / 分歧 / 退潮。
- 今日操作纪律：总仓位上限、单票上限、是否适合开新仓。
- 数据源与失败提示。

### 5.2 早间新闻

生成时间建议：交易日 08:30-09:00。

内容结构：

- 隔夜外围：美股、港股 ADR、人民币、美元指数、黄金、原油、重要期货。
- 宏观政策：央行、发改委、证监会、财政部、交易所。
- 产业新闻：AI、半导体、新能源、机器人、医药、军工等。
- 公司公告：业绩、增减持、重组、订单、监管问询。
- A 股映射：直接受益、间接受益、情绪映射，必须区分确定性。
- 今日重点观察：2-4 个方向，每个方向给验证条件。
- 风险提示：高位一致、消息兑现、外围扰动、业绩雷。

### 5.3 午间复盘

生成时间：交易日 11:30 自动生成。

内容结构：

- 上午指数表现和成交活跃度。
- 涨跌家数、涨停/跌停、炸板率、最高连板。
- 行业/概念资金流入流出。
- 主线确认或轮动情况。
- 上午强势股、负反馈股。
- 午后计划：继续进攻 / 只做核心 / 降仓防守 / 停止开新仓。

### 5.4 盘后完整版复盘

生成时间：交易日 21:00 后。

内容结构：

- 市场温度和情绪周期。
- 主线题材前三名：强度分、龙头、容量核心、20cm 核心、明日预期。
- 涨停票归因和连板梯队。
- 跌停、炸板和亏钱效应来源。
- 候选股票池：A 池龙头、B 池容量趋势、C 池 20cm 弹性。
- 明日买卖计划：触发条件、止损、仓位、失效条件。
- 持仓处理：持仓逻辑、是否失效、明日动作。
- 交易纪律复盘。
- 免责声明。

### 5.5 个股打分计算器

输入：

- 股票代码或名称。
- 可选：交易模式，`auto` / `leader` / `trend` / `20cm`。
- 可选：持仓成本、计划仓位、所属题材。

输出：

- 总分与动作：重点观察 / 标准候选 / 小仓试错 / 暂不参与 / 回避。
- 分项评分：趋势、MACD、位置、波动率、量价、回调质量、买点、风险、模式匹配。
- 关键指标：MA20、MA60、ATR、60 日位置、量比。
- 买入计划：触发条件，不给无条件买入指令。
- 止损计划：技术止损和 5%硬止损。
- 止盈计划：主线仍强持有，放量滞涨/板块退潮减仓。
- 仓位建议：结合市场温度和个股分数。
- 风险提示：一票否决项优先于分数。

现有 `calculator.py` 已覆盖技术评分，后续需要补齐题材、龙头地位、公告/新闻催化和市场温度联动。

## 6. 评分与交易规则

### 6.1 市场温度

- 强：放量、涨停多、跌停少、连板高度打开。总仓位上限 75%-100%。
- 中：指数震荡、题材局部活跃。总仓位上限 50%-75%。
- 弱：缩量、炸板高、跌停增加。总仓位上限 25%-50%。
- 冰：高位核按钮、跌停扩散、龙头断板 A 杀。总仓位上限 0%-25%。

### 6.2 个股 100 分模型

基础模型沿用 `短线游资交易系统.md`：

- 题材主线：15
- 龙头/容量核心/20cm 核心地位：15
- 情绪周期：10
- 量价结构：15
- MA20 趋势：10
- 位置安全：10
- 买点质量：10
- 风险可控：10
- 预期差：5

现有计算器技术分可作为技术子分；最终产品分需要合并题材、地位、市场情绪和风险否决。

### 6.3 一票否决

- 情绪退潮且高位亏钱效应扩散。
- 个股连续放量滞涨或高位长上影。
- 跌破 MA20 后反抽无力。
- 止损距离超过可承受范围。
- 单笔亏损无法控制在 5%以内。
- 交易理由不是主线核心、标准买点或明确事件。

## 7. 数据与存储

### 7.1 数据源

优先级：

1. AkShare 封装的东方财富、同花顺、新浪接口。
2. 东方财富公开接口。
3. 腾讯/新浪行情接口。
4. 巨潮资讯、交易所公告、公司公告。
5. 财联社、证券时报、第一财经等新闻源。

要求：

- 每条快照记录数据源和生成时间。
- 允许接口失败，但必须写入 `errors`。
- 多源结果冲突时，保留主源值和备用源状态。
- 数据源失败时使用最近成功快照降级展示，不能展示空白页。

### 7.2 存储建议

MVP 可继续用 JSON 文件发布公网：

- `dashboard/data/daily.json`
- `dashboard/data/refresh-status.json`
- `dashboard/data/reports/YYYY-MM-DD/pre-market.json`
- `dashboard/data/reports/YYYY-MM-DD/noon.json`
- `dashboard/data/reports/YYYY-MM-DD/post-market.json`
- `dashboard/data/stocks/YYYY-MM-DD/{code}.json`

当报告数量和历史查询增加后，迁移到 PostgreSQL：

- `task_runs`
- `market_snapshots`
- `reports`
- `stock_scores`
- `watchlists`
- `positions`
- `trades`
- `trade_reviews`
- `data_source_events`

第一版如果想更轻，可以用 SQLite/DuckDB 作为本地快照库，再导出 JSON 给公网。

## 8. 推荐系统架构

### 8.1 MVP 架构

```text
GitHub Actions 定时任务
  -> Python 数据采集脚本
  -> JSON 快照/报告生成
  -> 静态看板构建
  -> GitHub Pages 发布
```

优点：成本低、稳定、易公开、无需服务器运维。

限制：动态个股查询不适合完全依赖 GitHub Pages。计算器如果要公网实时输入，需要后端服务或预生成热门股票评分。

### 8.2 推荐演进架构

```text
数据源
  -> 采集任务 Worker
  -> PostgreSQL / SQLite 快照库
  -> 评分引擎 + 报告引擎
  -> API 服务
  -> Web 前台
  -> 静态报告归档 / GitHub Pages / 自建站
```

建议路径：

1. 先扩展现有 GitHub Pages 静态看板。
2. 个股计算器先做成本地/后台 API。
3. 若团队高频使用，再部署一台云服务器运行 API、数据库和定时任务。
4. 订阅制阶段再加登录、权限、支付和内容分层。

## 9. 定时任务设计

| 任务 | 时间 | 产物 | 失败策略 |
|---|---:|---|---|
| 早间新闻 | 08:30 | `pre-market.json` / 早报页面 | 使用已抓新闻和缓存，标记低置信 |
| 午间复盘 | 11:30 | `noon.json` / 午报页面 | 保留上一快照，显示失败原因 |
| 收盘快照 | 15:30 | `daily.json` | 保留上一份可用数据 |
| 盘后完整版 | 21:00 | `post-market.json` / 完整报告 | 缺公告/新闻时降级为行情复盘 |
| 静态发布 | 每次报告后 | 根目录页面和数据 | 构建失败不覆盖旧站 |

任务状态字段：

- `task`
- `phase`
- `tradeDate`
- `startedAt`
- `finishedAt`
- `success`
- `message`
- `sources`
- `errors`
- `lastSuccessfulAt`

## 10. 页面信息架构

### 10.1 首页

- 顶部：日期、阶段、生成时间、任务状态、免责声明入口。
- 第一屏：今日市场状态。
- 第二屏：早间/午间/盘后报告切换。
- 第三屏：主线题材与资金流。
- 第四屏：候选股票池与明日计划。
- 第五屏：风险雷达与负反馈。
- 底部：历史报告归档。

### 10.2 个股页 / 计算器

- 输入框：代码或名称。
- 模式选择：自动、龙头、容量趋势、20cm。
- 结果摘要：评分、动作、仓位、置信度。
- 分项评分。
- K 线关键位和止损位。
- 买卖计划。
- 风险提示和一票否决。

- 按日期查看早报、午报、盘后报告。

- 按股票查看历史评分记录。

## 11. MVP 开发拆分

### 阶段 1：复盘报告自动化

- 扩展 `daily.json` 数据结构，增加 `reports`。
- 新增报告生成脚本：`dashboard/scripts/generate_reports.py`。
- 增加早间、午间、盘后报告模板。
- 在看板增加报告切换区域。
- 将 workflow 调度从 2 次扩展到 3-4 次。

### 阶段 2：交易计划与股票池

- 把 `短线游资交易系统.md` 中的股票池规则落成代码。
- 输出 A/B/C 三类候选池。
- 将个股计算器结果并入候选池。
- 明日计划输出买点、止损、仓位和失效条件。

### 阶段 3：公网计算器

- 短期方案：预生成候选股评分 JSON，前端展示。
- 中期方案：部署轻量 API，调用 `calculator.py` 实时计算。
- 支持股票名称到代码映射。
- 增加市场温度对仓位建议的联动。

### 阶段 4：历史快照与内部复盘

- 保存每日完整快照。
- 增加历史报告列表。
- 增加持仓、交易记录、买入理由、卖出归因。
- 支持阶段性复盘：哪些规则有效、哪些规则失效。

### 阶段 5：订阅制准备

- 内容分层：公开摘要、完整报告、个股计划。
- 登录和权限。
- 付费订阅。
- 邮件/RSS/浏览器推送。
- 合规文案和用户协议。

## 12. 合规与风险提示

所有公网页面底部和报告正文末尾都应包含：

```text
免责声明：本页面内容仅为个人/团队交易复盘、数据整理与策略研究记录，不构成任何投资建议、收益承诺或买卖依据。市场有风险，交易需独立判断并自行承担风险。
```

买卖计划表达建议：

- 使用“观察、触发、失效、仓位上限、风险条件”。
- 避免使用“必涨、稳赚、无脑买入、保证收益”等表达。
- 明确所有计划都是条件式，不是无条件交易指令。

1. 新增报告数据结构，支持早间、午间、盘后三个阶段。
2. 在首页增加“报告切换”和“任务状态”模块。
3. 把 21:00 盘后完整版加入 GitHub Actions。
4. 将个股计算器接入候选股票池，先预生成结果。
5. 增加免责声明和历史归档目录。

建议保持第一版公网为 GitHub Pages，计算器先采用预生成候选池方案。等小团队真正高频使用后，再上云服务器和数据库。
